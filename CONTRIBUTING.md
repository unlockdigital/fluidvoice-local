# Contributing to FluidVoice Local

Start with a focused issue describing the current behavior, expected result, platform and reproducible evidence. Agree on major feature and privacy-boundary changes before implementation. Keep Mac and Windows code scoped and preserve working installations and user data.

Changes should include the relevant deterministic verification and honest reporting of skipped hardware or platform checks. Use fake speech/text and redact credentials and personal data. Human review covers the full diff and test claims for AI-assisted contributions; briefly disclose AI use and the verification performed. Preserve GPL, upstream/third-party notices and independent source provenance.

Public source previews and supported platform binaries have separate gates. Review HANDOFF.md before changing Mac input, signing or installation. Windows contributor instructions are in platforms/windows/AGENTS.md. macOS 27 qualification is a separate documented work stream.

Reusable fixes can also be proposed upstream. Reproduce the issue on current altic-dev/FluidVoice, follow its current issue/discussion/approval policy, and submit one focused change with human-reviewed evidence. This fork maintains its strict profile independently.
