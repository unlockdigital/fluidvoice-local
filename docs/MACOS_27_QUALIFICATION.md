## Read-only readiness probe

From the repository root, run:

```sh
bash scripts/check-macos27-readiness.sh
```

The wrapper compiles `scripts/fixtures/MacOS27Readiness.swift` using the existing macOS Swift toolchain. Its binary, module caches and suppressed diagnostics live in a fresh `/private/tmp/fluidvoice-macos27-readiness.*` directory, removed on exit. Compilation requires an existing SDK/toolchain. The probe performs these bounded observations:

- `ProcessInfo.operatingSystemVersion` checks the actual host major version.
- Foundation reads only the canonical per-user `Library/Input Methods/FluidVoice Direct Input.app` bundle's installation/Info.plist metadata and the known private helper location. Redirected canonical bundles or metadata outside the bundle are rejected. The probe prints fixed descriptions and canonical fork identifiers, with local paths and arbitrary metadata omitted.
- Security static-code APIs check the canonical signing identifier, strict resource integrity, all architectures and nested code in standard locations. `kSecCSNoNetworkAccess` disables network-dependent validation. The native-slice signed entitlement dictionary is compared with the one-key microphone-input boundary. Trusted publisher, notarization and cross-slice entitlement equivalence remain separate artifact-review checks.
- Public `TISCreateInputSourceList` and `TISGetInputSourceProperty` inspect only matching canonical parent/mode records, including disabled records. Exactly one parent/mode and their enabled/select-capable/selected flags are reported separately. Missing Boolean properties stay unavailable. A nil query stays unavailable; an empty successful query reports zero matches. These are instantaneous catalog observations; catalog IDs alone leave the loaded bundle's path and provenance unresolved.

The report distinguishes `OBSERVED`, `ATTENTION`, `UNAVAILABLE`, and `REQUIRED` physical acceptance. A successful report always says `Qualification: PENDING_PHYSICAL_ACCEPTANCE`. Even `observations-complete` describes only the rows inspected. Every live or fixture report exits **3** for qualification pending; deterministic self-tests exit **0** on success, and usage/toolchain/probe failures exit **2**. Treat exit 3 as a completed observation with remaining qualification work. On macOS 26 the report explicitly says `HOST-MISMATCH` and qualification pending.

The probe contains only observation calls. It leaves registration, enable/selection/persistence, launch agents, preferences, TCC, microphone capture, inference, app launches, installation and signing untouched. It reads neither document content nor arbitrary current-source identities, process lists, Secure Input owner details, device inventories or TCC databases. Its output can be retained as sanitized readiness evidence. The wrapper buffers output and suppresses framework/compiler diagnostics that could contain local paths.

Exercise deterministic reporting without inspecting the host installation or TIS state:

```sh
bash -n scripts/check-macos27-readiness.sh
bash scripts/check-macos27-readiness.sh --self-test
bash scripts/check-macos27-readiness.sh --fixture host26
bash scripts/check-macos27-readiness.sh --fixture observed27
```

Additional fixtures: `missing27`, `invalid27`, `unavailable27`, `duplicate27`, `incomplete27`, `disabled27`. Each fixture report is visibly `SIMULATED`, exercises the same report logic, and exits 3. `observed27` proves that apparently complete observations still leave physical qualification pending. The self-tests also cover reporting for unexpected/redirected installation states and distinguish false flags from unavailable flags. These tests validate reporting; native API observation and physical acceptance have their own evidence.
