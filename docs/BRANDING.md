# Purpose and project identity

Project name: **FluidVoice Local**. Tagline: **Private voice input for the applications you choose.** Description: **Privacy-preserving local transcription and dictation for everyday applications and LLM workflows.**

The fork exists to make dictating to a computer useful throughout ordinary work while maintaining a clear local speech-processing boundary. People can speak instructions, questions, drafts and revisions into editors, notes, browser fields, LLM chats and coding agents. The maintained profile uses local ASR and disables cloud transcription/enhancement, telemetry, retained audio/transcript history, content logging, Command Mode, the Local API and update checks.

Describe these as implemented profile controls with platform-specific verification. Give users a clear account of destination behavior: the chosen application governs storage, networking and submission after receiving text. Local voice input supports local and cloud-based destinations without silently changing the speech-processing policy. Compatibility claims follow the native acceptance matrix.

Use the independently maintained derivative name with prominent credit to altic-dev/FluidVoice and contributors. Preserve GPL and third-party notices. The repository mark uses an original microphone-and-shield motif; native bundle/input-source identifiers remain stable for compatibility. The Windows source retains its separately credited FluidVoice-derived mark until a validated native asset change.

Preferred phrases include local speech recognition, privacy-preserving dictation, secure local processing profile, application-wide voice input, and LLM/coding workflows. Tie stronger privacy or security claims to the actual controls and qualification evidence in spec/PRIVACY_PROFILE.md and docs/VALIDATION.md.

## Naming and compatibility

The canonical repository is [unlockdigital/fluidvoice-local](https://github.com/unlockdigital/fluidvoice-local), and the local community checkout is named `FLUIDVOICE-LOCAL`. The maintained branch remains `hardened`, describing its processing profile. The project adopted FluidVoice Local on October 28, 2026; earlier source snapshots, commit authors and validation records retain their historical names.

New Mac products use `FluidVoice Local.app` and the display name `FluidVoice Local Direct Input`. The packaged input method is `build/FluidVoice Local Direct Input.app`. Its established installation location remains `~/Library/Input Methods/FluidVoice Direct Input.app`, keeping the guardian and registration route consistent. Bundle/input-source IDs, preference domains, Keychain services and private storage directories retain their existing `FluidVoiceHardened` identities. These technical values preserve permission and state continuity. A later installation trial still requires the documented preservation and physical acceptance procedure.

Windows products use `FluidVoice Local` display and executable names; the Windows README documents installation-path handling. Original GPL notices, upstream names, source-origin ledgers and reviewed third-party references retain their original attribution. Future changes to executable paths or OS identities require explicit migration and host acceptance.
